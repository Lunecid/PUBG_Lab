## 2. 처리 계약

요구는 서로 다른 맵과 가변 팀 규모에서 같은 정보 조건으로 개인·팀 이동을 학습하는 것이다.
고정 Erangel 범위와 4인 잘림을 제거하고, 관측 입력과 미래 정답의 저장 경로를 나눈다.

- 시계: 실제 `event_time - match_start` 초. 기존 elapsed_time 오프셋을 입력 시계로 쓰지 않는다.
- 공식 종료 사건이 유일하면 그 이후 모든 로그를 상태·정답·공간 연결 구성 전에 분리한다.
  종료 후 로그는 원천 추출물과 제외 수에 보존한다. 이는 승리 후 대기일 수 있어 오류로 단정하지 않는다.
- 좌표: API cm를 m로 변환. 100m 셀은 `(floor(x/100), floor(y/100))`.
- 입력: 10초 간격, 최대 과거 120초(13프레임), 30초 간격 anchor.
- 정답: 10–60초 6시점. 보간은 정답에만, 간격 15초 이하·동일 생명/유효 연결 구간·이동 모드에서 허용.
- anchor 선택: 현재 정보만 사용. 미래 정답 존재 여부로 anchor를 선별하지 않는다.
- 결측: 0 채움과 별도 마스크. 이력을 따라 복원한 장비도 실제 완전한 소지품·탄약 수량과 구별한다.
- 재진입: 사망 이후 직접 항공기 증거와 복수 위치 기반 추정을 별도 confidence로 저장.
- 차량: 클래스·이동 모드의 기록이다. 차량 고유 인스턴스나 실제 공유 탑승을 추정하지 않는다.
- 과도한 속도·관측 공백: 오류로 단정하거나 좌표를 잘라내지 않고 연결 구간을 끊어 문제 색인에 남긴다.
- 참가자: 명단 밖 위치·사건은 제외 수를 남긴다. 이름·계정 ID 대신 경기 내부 정수 ID를 저장한다.

공간 연결은 맵 × 추정 패치별로 따로 저장한다. 학습 경기에서만 관측 지지 수와 경기 수를 집계한다.
미관측 4방향 이웃은 추정 인접성이고 통행 가능/불가능의 정답이 아니다.
40.2 연결을 41.1에서 관측한 연결로 이름 바꾸지 않는다.
따라서 41.1 검증 그래프의 관측 공간 지지는 없을 수 있으며, 이 조건 자체가 시간 일반화 평가의 일부다.
정밀 지형·건물·교량·충돌 정확도를 입증하는 데이터가 아니다.

## 3. 정보 범위와 결과 라벨

관측자는 자기 상태·장비·교전 기록과 팀 HUD의 위치/체력 근사를 사용한다.
서버는 시점까지의 전체 참가자 상태를 사용한다.
관측자 가림을 개인 특징에 먼저 적용한 뒤 팀 특징을 집계한다.
서버의 적 위치나 팀원의 비공개 장비를 집계 후 가리는 방식은 허용하지 않는다.
피해 사건은 교전 증거이며, 무피해를 미인지로 해석하지 않는다.
실제 시야·소리·자기장 발표 지연은 검증된 입력이 아니다.

최종 순위·우승은 정답 전용이다. 팀 결과의 범위·유일성·우승 일관성을 확인하고 개인 순위와 대조한다.
불일치는 원본 값을 보존하고 해당 결과 손실을 마스킹한다. 순위와 우승 마스크는 별개다.
이 대조는 독립적인 정답 판정이 아니라 필드 간 일관성 확인이다.
마지막 사망 기록만으로 최종 팀 탈락 시각을 확정하지 않으며 terminal_time_mask는 현재 모두 False다.
P4는 미래에 기록된 피해와 사망 사건, 경기 종료에 따른 우측 검열 마스크를 제공한다.

## 4. 제거 실험 준비

모든 실험은 학습 40.2 / 검증 41.1을 유지한다.
전체 맵과 단일 맵, 맵 제외, 인칭별/인칭 제외, 인원별/인원 제외,
공간 제거·관측 연결만·팀 노드 제거·결과 학습 제거·짧은 이력·사전학습 없음,
정보 범위와 조건 변수 제거를 위한 목록을 생성한다.
학습/검증 표본이 없는 도메인은 평가 가능한 실험으로 세지 않는다.
실제 모델 학습과 성능 ablation을 수행했다는 뜻은 아니다.

공간 지지와 어휘는 ablation의 정확한 학습 ID로 다시 제한한다.
정규화는 이번에 적합하지 않고 물리 단위를 보존한다.
추후 적합하는 통계도 각 ablation 학습 자료만 사용해야 한다.
관측자/서버 비교는 같은 anchor·정답·정보 이력 길이로 평가한다.

## 5. 반증 시험·비용·보존

미래 suffix 삭제 입력 불변, 미래 결과 변조 입력 불변, 서버 비공개 상태 변조 관측자 불변,
재진입 경계 연결 차단, 5인 팀 무잘림, 문제 시각 중복·공백, 패치 시간대/점검 경계 검사를 포함한다.
전처리는 CPU 실행이다. 원천 DB는 SELECT/SHOW 전용이며 비밀번호는 숨김 입력 후 메모리에서만 사용한다.
경기 단위 처리로 전체 원천 자료를 RAM에 적재하지 않는다. 실측 시간·RSS·파일 해시를 실행 기록에 남긴다.
완료 데이터는 동결하고 수정 실행은 새 버전으로 남긴다.

코드:
`world_model/preprocess.py`, `world_model/patches.py`, `world_model/dataset.py`,
`tools/world_model_preprocess.py`, `tools/verify_world_model_preprocess.py`.
설계 근거는 전체 코퍼스 V2, 기존 V4 실패 분석, 품질 감사다.
HGT(arXiv:2003.01332)의 유형별 관계를 데이터 인터페이스에 참고했으며 모델 구현·재현을 주장하지 않는다.
