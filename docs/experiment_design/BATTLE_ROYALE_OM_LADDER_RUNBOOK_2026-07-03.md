# Battle Royale OM Ladder Runbook

Date: 2026-07-03
Class: `ExperimentRunbook`
Lifecycle: `active`

## Purpose

This runbook defines how OM0-OM6 experiments are executed and how artifacts are
managed.

The rule is:

```text
one map / perspective / team-size cohort
one independent run directory
one shared split inside that cohort
one OM0-OM6 matrix result
```

The broad `full` preset is not the headline ladder.  It is reserved for later
upper-bound or stress-test comparisons.

## Stage Order

| Stage | Name | Role | Output Root |
| --- | --- | --- | --- |
| S0 | representative smoke | verify execution on TPP squad, TPP duo, FPP squad | `model_stgcn/checkpoints/om_ladder_*_smoke30` |
| S1 | required cohort OM ladder | headline cohort-separated OM0-OM6 runs | `model_stgcn/checkpoints/br_om_ladder_required_v1` |
| S2 | run-level aggregation | combine per-cohort matrix metrics | `om_ladder_metrics_all_cohorts.csv` |
| S3 | sensitivity / stress | optional `full`, graph-relation, seed-repeat, or auxiliary-cohort runs | separate named roots |

`model.pt` alone is not treated as a completed artifact. An experiment is resumable only after `train_complete.json` exists, or after the evaluation JSON already exists from a previous completed run.

The run root must contain:

```text
run_index.tsv
om_ladder_metrics_all_cohorts.csv
om_ladder_metrics_summary.json
```

`run_index.tsv` is the append-only execution log.  The aggregated CSV is
generated by:

```bash
python3 tools/collect_om_ladder_metrics.py \
  --root model_stgcn/checkpoints/br_om_ladder_required_v1
```

## Interpretation Rule

Do not interpret a pooled result first.

Interpretation order:

1. Within each cohort, compare OM0 through OM6.
2. Then compare whether the same OM increments recur across cohorts.
3. Only after cohort-level results are stable, report macro and weighted
   summaries.
4. Use `full` only as an upper-bound or stress condition, never as the first
   ontology result.
