# 모듈화·프로젝트화 적용 상태

날짜: 2026-10-26. 확인 기준: 정리 브랜치 r2와 main 병합 작업 트리.
책임: 실제 구조와 미완료 항목을 구분한다. 새 모델 아키텍처 제안이나 승인 기록이 아니다.

**동일 모듈의 코드를 부품으로 나누고 같은 폴더에 모으는 정리는 전부 완료되지 않았다.**
앞선 정리는 버전 색인·해시·캐시 삭제·이력 보존이었다. 물리적인 코드 재배치·공통 부품 추출을 수행하지 않았다.
main 병합도 이 상태를 모듈화 완료로 바꾸지 않는다.

| 확인 항목 | 실제 상태 | 판정 |
|---|---|---|
| 연구·모델·원고 버전 구분 | 8개 계열의 registry와 릴리스 manifest | 적용 |
| 기존 패키지 분리 | `world_model/`, `movement_diffusion/`, `stdb/`, `model_stgcn/ptr/` 등 | 일부 적용 |
| 동일 계열 실행 도구의 폴더 집중 | `tools/` 바로 아래 Python 파일 115개. World model 관련 18개, SAC 관련 44개가 함께 있음 | 미완료 |
| 재사용 부품과 명령 진입점 분리 | `tools/`의 37개 파일과 World model 시험 파일 2개가 `tools.*`를 import | 추가 점검·분리 필요 |
| 설치 가능한 프로젝트 정의 | 루트 `pyproject.toml`, `setup.py`, `setup.cfg` 없음 | 미적용 |
| 부품별 단일 책임·공개 인터페이스·의존 방향 | 저장소 전체에 대한 검증과 재구성을 수행하지 않음 | 완료로 판정할 수 없음 |

파일 수는 해당 폴더의 직접 하위 `.py` 파일을 기준으로 했다. 보호 분할 모듈은 내용 조회와 집계에서 제외했다.
숫자만으로 모듈 설계의 좋고 나쁨을 판정한 것이 아니다. CLI 코드가 실제로 재사용되므로 이름만 옮겨서는 부족함을 보여주는 현황이다.
기존 graphify AST의 WorldEncoder·TrajectoryDataset·DynamicSTGNN 경로도 참고했으며, main에서 추가된 수집기를 새로 전수 분석한 그래프라고 주장하지 않는다.

## 남은 구조 변경의 경계

다음 구조 변경에서는 모듈별 책임·입출력·공개 API를 정하고,
같은 기능의 재사용 부품·CLI·시험을 대응시키며 기존 호출 경로의 호환성을 검증해야 한다.
우선 정리 대상은 World model 실행·검증·보고 도구, SAC 도구, 공통 입출력·실행 메타데이터다.
실제로 중복된 구현인지 확인한 뒤 공통 부품으로 추출하며, 파일 이름이 비슷하다는 이유로 합치지 않는다.

모집단·분할·시간 경계·모델 수식·평가 판정은 구조 정리로 변경하지 않는다.
과거 실행의 코드 snapshot과 원고별 재현 자료는 원위치에 보존한다.
설계와 파일 이동·호환 경로 패치를 제시한 뒤 B3·B7의 승인 범위에서 수행할 작업이다.
