# PUBG 폴더 정리·버전 관리 (2026-10-26)

저장소 정리 릴리스: **2026.10.26-r1**. 연구 모델의 새 성능 버전이 아니다.
원격: [Lunecid/PUBG_Lab](https://github.com/Lunecid/PUBG_Lab), 공개 저장소.
작업 브랜치: `codex/organize-versions-20261026`.

## 승인과 적용 원칙

사용자는 LOL TEAMFIGHT 정리 원칙, 버전별 관리, 정크 삭제와 GitHub commit·push를 직접 요청했다.
프로젝트의 WORKING_RULES C2·I1·I4·I7·I9와 PUBG_APPLICATION의 보존 경계를 적용했다.
이전 LoL 대화의 구조 정리에서도 현재 지침의 입구와 과거 기록을 구분하고 원 연구 기록을 보존했음을 확인했다.
다른 프로젝트의 연구 설계·모델 배정·전역 하네스를 PUBG에 자동 이식하지 않았다.

## 버전과 폴더

루트 README와 [버전 색인](../../../versions/README.md)에 8개 연구·원고 계열을 구분했다.
저장소 릴리스, 모델 V1–V4, 전처리 v3, G1–G4, 원고 v13–v20은 별개 축이다.
원래 코드·원고·완료된 실행 경로는 유지해 import와 증거 링크의 위치를 보존했다.
이동 V4의 실패·World model G4의 판정 미달도 기존 기록대로 보존했다.
과거 원고 안의 동일한 build script들은 릴리스별 재현 자료이므로 중복이라는 이유로 지우지 않았다.
고아처럼 보이는 초기 코드 역시 원본·재현 자료 여부를 배제할 수 없어 보존했다.

## 삭제 사전 기록

최종 삭제 대상은 **377개, 9,866,570 bytes (9.41 MiB)**다.
Python/test 캐시, Finder 메타데이터, 인용되지 않은 재생성 가능 LaTeX 보조 파일만 포함한다.
[경로·크기·이유·해시](deletion_execution_plan.json)를 삭제 전에 저장했다.
기존 증거 snapshot이 인용하는 보조 파일 5개와 완료 보고서 폴더의 메타데이터 5개는 보존한다.
`.log`, 실패 시도, 원본, 원시 데이터, 가중치, 잠금 분할, 참조 코드, worktree, 가상환경은 삭제하지 않는다.
첫 참조 검사에 새 감사 폴더가 포함되는 보수적 오탐을 발견해 v2로 정정했다. 두 사전 기록 모두 남겼다.
삭제 후 [영수증](deletion_receipt.json)으로 실제 처리 수와 파일 부재를 대조한다.

## Git에 올릴 범위

미추적 행 단위 예측·진단 CSV **161개, 978.58 MiB**는
원래 위치에 보존하고 [경로·크기·SHA-256](local_artifacts.json)으로 연결했다.
이 파일들에 대한 ignore 규칙을 확인했다. 이미 추적된 소규모 집계 증거는 유지했다.
`.idea/` 설정 6개는 로컬에서 유지하고 Git 색인에서만 제외했다.
비밀 설정과 보호 분할 모듈 본문은 열거나 해시하지 않았다. 기존 추적 분할 파일은 변경하지 않았으며, 새 비밀 분할 구현은 추가하지 않는다.
과거 Git 이력을 지우거나 비밀 제거가 완료됐다고 주장하지 않는다.

## 릴리스 확인과 한계

```sh
python3 tools/repository_release.py verify --release 2026.10.26-r1
```

릴리스 manifest는 공개 대상 파일의 동일성을 고정한다. 성능이나 데이터 재현 성공의 증명이 아니다.
대용량 로컬 자료·비밀 모듈은 클론만으로 복원되지 않는다.
원고 안의 기존 로컬 증거 링크는 해당 자료가 있는 환경에서만 열린다.
저장소는 별도 브랜치와 릴리스 태그로 push하고, 기본 브랜치 병합·게재·배포는 이번 정리 결과로 간주하지 않는다.

추가 점검: staged diff 공백 검사는 보존한 기존 파일 49개에서 경고를 냈다.
각 파일은 정리 전 해시와 일치하며, 원고 템플릿·과거 재현 코드의 내용 보존을 위해 공백을 일괄 수정하지 않았다.
[원 경고](staged_diff_check.txt)는 그대로 남겼다. 이번에 새로 작성·변경한 정리 파일의 공백 검사는 별도로 통과했다.
